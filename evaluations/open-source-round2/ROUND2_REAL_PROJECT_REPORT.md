## ActionTaint Finding

ActionTaint reported one finding in `saas-starter-kit`:

| Field | Value |
|---|---|
| Severity | `MEDIUM` |
| Type | Open Redirect |
| Source | `src/lib/actions/billing.ts::createCheckoutSession(planId)` |
| Sink | `src/lib/actions/billing.ts:70` |
| Sink snippet | `redirect(session.url);` |
| Reported path | `planId -> getPriceId(planId) -> priceId -> stripe.checkout.sessions.create(...) -> session -> redirect(session.url)` |

Relevant code:

```ts
export async function createCheckoutSession(planId: string) {
  const priceId = getPriceId(planId);
  const session = await stripe.checkout.sessions.create({
    line_items: [{ price: priceId, quantity: 1 }],
    success_url: `${env.NEXT_PUBLIC_APP_URL}/billing?success=true`,
    cancel_url: `${env.NEXT_PUBLIC_APP_URL}/billing?canceled=true`,
  });

  redirect(session.url);
}
```

Manual triage:

- This is probably not a confirmed real vulnerability.
- `planId` is client-reachable, but `getPriceId(planId)` maps the value through a local allowlist-like object containing only `basic` and `pro`.
- `redirect(session.url)` redirects to a URL returned by Stripe's checkout session API, not directly to a user-supplied URL.
- The finding is useful as an over-taint case: ActionTaint currently treats the Stripe session object as tainted because it was created with a tainted `priceId`, even though the redirect target is generated by a trusted payment provider.

Reviewer interpretation: this should be reported as a triage finding / false positive, not as a disclosed vulnerability.

## Default CodeQL Baseline

Default CodeQL produced findings in several projects, but they are not directly equivalent to ActionTaint results. Most are broad JavaScript security findings such as log injection, request forgery, XSS, weak sanitization, or password hashing warnings. ActionTaint is narrower: it only reports flows that start at reconstructed client-reachable Server Action boundaries.

## Interpretation

Round-2 did not confirm a new production vulnerability. This is still a useful result:

1. ActionTaint scaled to larger real-world projects such as `dub-web` and `formbricks-web`.
2. It found Server Actions and client-reachable actions in modern codebases.
3. It produced very low noise: one triage finding across five projects.
4. The single finding revealed a concrete precision improvement: ActionTaint needs a trusted-return model for provider-generated redirect URLs such as Stripe Checkout sessions.
5. Some selected repositories were not ideal Server Action benchmarks: `papermark` had no TypeScript/TSX Server Actions in the cloned code, and `documenso`'s relevant Next.js subapp had no Server Actions.

## Methodological Note

This evaluation should not be described as "ActionTaint found a confirmed vulnerability in production." A paper-safe wording is:

> In a second round of real-world open-source testing, ActionTaint analyzed five additional projects or Next.js subapps. It found Server Actions and client-reachable actions in several large codebases, produced one triage finding in a SaaS starter, and no confirmed vulnerabilities after manual review. The triage finding exposed a precision limitation around provider-generated redirect URLs, motivating future trusted-return modeling.
